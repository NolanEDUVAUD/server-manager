# Internationalisation FR / EN

**Version cible :** 0.3.0 (Phase 1.6)

## But

Toute l'interface existe en **français** (langue par défaut) et en **anglais**. La langue se choisit dans Paramètres → Général et s'applique immédiatement, sans redémarrage.

## Choix techniques

- Module maison `src/i18n/`, sans dépendance : une fonction `t()`, un hook `useT()` et un petit store zustand pour la langue active. i18next aurait ajouté environ 50 Ko et une configuration asynchrone, pour un besoin qui tient en une centaine de lignes.
- Dictionnaires en TypeScript, **un fichier par espace de noms** et par langue (`src/i18n/fr/<ns>.ts`, `src/i18n/en/<ns>.ts`) : plusieurs personnes peuvent traduire en parallèle sans conflit. `docs/superpowers/tools/gen_i18n_index.py` régénère les deux `index.ts`.
- `fr` est la référence ; `en` est typé `Dict` (`typeof fr`). Une clé manquante ou en trop **casse la compilation**, et les clés passées à `t()` sont typées (`TKey`).
- Variables `{nom}`. Pluriels `{ one, other }` choisis par `Intl.PluralRules` (« 0 serveur » en français, « 0 servers » en anglais).
- Dates et nombres : `locale` (via `useT()`) ou `currentLocale()` — `fr-FR` ou `en-GB`.
- Les textes affichés sont traduits **au moment de l'affichage**, jamais à l'import d'un module. Les tables de données (modules, catalogue, raccourcis, méthodes d'authentification…) portent des clés, pas des textes.
- Côté Rust : `settings.general.language` (`fr` par défaut, validé), et le menu de la zone de notification traduit.

## Limites assumées

- Les messages d'erreur **détaillés du backend Rust** (échec SSH, API Proxmox, validation) restent en français. Le réglage de la langue le signale.
- Les journaux et les commentaires du code restent en français.
- Les phrases de confirmation du lab existent dans les deux langues : le backend accepte l'une ou l'autre, sans jamais confondre arrêt et démarrage.

## Tests

- `i18n.test.ts` : chaque clé existe dans les deux langues ; aucune traduction n'est vide ; mêmes variables `{nom}` dans chaque langue ; chaque pluriel a sa forme `other` ; comportement de `t()` (variables, pluriels, repli).
- `untranslated.test.ts` (**garde-fou**) : analyse chaque `.tsx` avec le compilateur TypeScript. Il échoue s'il reste du texte visible écrit en dur : texte JSX, `title`, `placeholder`, `aria-label`, `label`, `message`, messages de toast. Seuls les noms propres et les valeurs techniques listés dans `UNIVERSAL` sont tolérés.
- Un test en anglais par grand ensemble de l'interface : ossature et palette, supervision, opérations, serveurs et clés SSH.
